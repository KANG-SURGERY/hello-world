# policy-sim — 부동산 대책 인과효과 추정

정책이 실제로 어떤 결과를 냈는지를 과거 자연실험에서 정량 추정하는 도구입니다.
"1년 뒤 집값을 맞히는" 프로그램이 아니라, **이 정책 레버 조합이 과거에 어떤 효과와
어떤 부작용을 냈고 그 불확실성이 얼마인가**를 답하는 것이 목표입니다.

정책은 무작위배정이 불가능하므로 RCT를 쓸 수 없고, 관찰자료의 자연실험에 의존합니다.
임상연구로 옮기면 이런 대응입니다.

| 임상연구 | 여기 |
|---|---|
| RCT 불가 → 관찰연구 | 규제지역 지정을 자연실험으로 사용 |
| 시점·대조군 보정 | Difference-in-Differences / event study |
| 교란변수 보정 | 지역·월 고정효과 |
| 측정도구 검증 | 합성데이터로 추정기 사전 검증 (`validate_estimators.py`) |

## 빠른 시작

```sh
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python scripts/validate_estimators.py          # 데이터·API 키 없이 바로 실행됨
```

이 검증은 **참값을 심어 놓은 합성데이터**로 추정기가 그 값을 복원하는지 확인합니다.
실데이터에 쓰기 전에 반드시 통과시키세요. 복원하지 못하는 추정기가 실데이터에서
내놓는 숫자는 아무 의미가 없습니다.

## 실데이터

```sh
export MOLIT_API_KEY=...          # data.go.kr 에서 발급
python scripts/fetch_transactions.py --regions 11110 --from 2024-01 --to 2024-03   # 먼저 소량으로 확인
python scripts/fetch_transactions.py --all-seoul --from 2015-01 --to 2021-12
python scripts/run_event_study.py --policy 2018-08-27 --allow-unverified
```

`molit.py`는 **실제 API 응답으로 검증되지 않았습니다** — 작성 환경에서 data.go.kr
접근이 네트워크 정책으로 차단돼 있었습니다. 첫 호출은 검증 단계로 취급하세요.
응답 스키마가 바뀐 경우를 대비해 파서가 미매핑 필드를 보고합니다.

## 파이프라인

```
거래 원자료
  → hedonic.build_index()     품질보정 가격지수 (시군구 × 월)
  → event_study.run()         지역·월 고정효과 + 사건시점 계수
  → 처치효과 + 파급효과 + 진단
```

### 이 도구가 다루는 세 가지 함정

**1. 구성편의.** 규제 후에는 거래되는 아파트의 구성이 달라집니다(고가·대형 거래가
먼저 마릅니다). 단순 평균가격은 개별 아파트 가격이 그대로여도 하락합니다. 합성데이터
검증에서 이 편의만으로 효과가 **-0.036 → -0.080**으로 부풀었습니다. 헤도닉 보정이
이걸 제거합니다.

**2. 풍선효과(SUTVA 위반).** 인접 비규제지역이 오릅니다. 이들을 대조군에 넣으면
대조군 자체가 올라가 처치효과가 그만큼 과대추정됩니다(**-0.036 → -0.044**).
`include_spillover=True`가 인접지역에 별도 경로(θ)를 주어 분리하며, 이 θ가
곧 풍선효과의 추정치입니다 — 제거할 잡음이 아니라 측정할 부작용입니다.

**3. 기준시점 잡음.** 모든 계수를 k=-1 한 달에 정규화하면 그 달의 표본오차가 사후
계수 전체로 전파됩니다. 처치군이 4개 지역뿐일 때 이 오차가 **참값의 1/3**만큼
ATT를 움직였습니다. ATT를 `평균(사후) − 평균(사전)` 대비로 정의해 제거합니다.

### 진단

- **사전추세**: 23개 계수 결합검정은 군집이 25개뿐이라 rank가 모자라 p값이
  무의미합니다. 1자유도 **선형 기울기 대비**로 대체했습니다.
- **탐지가능 최소 기울기**: 이 검정이 80% 검정력으로 잡을 수 있는 최소 위배 크기를
  함께 보고합니다. 사전추세 검정 통과는 평행추세의 증거가 아닙니다 — 검정력이 낮아
  통과가 기본값에 가깝습니다.
- **wild cluster bootstrap**: 군집 25개에서 군집robust 점근이론은 CI를 과소추정합니다.
  보고할 때는 부트스트랩 쪽을 쓰세요.

### 현재 설계의 한계 (중요)

합성데이터 기준으로 8·27형 설계(처치 4개 구)의 **탐지가능 최소 기울기는
0.00265 log-pt/월**이고, 이는 사후 24개월에 누적되면 **약 0.033 log-pt**의 허위효과를
만듭니다. 추정 ATT(-0.034)와 거의 같은 크기입니다.

즉 **이 설계는 자기가 추정하는 효과만 한 크기의 가짜 효과를 배제하지 못합니다.**
처치 단위를 늘려야 합니다 — 여러 대책을 함께 추정하거나, 시군구가 아니라 읍면동
단위로 내려가는 것이 방향입니다.

## 정책 원장 (`config/policies.yaml`)

각 대책을 자연어가 아니라 레버 벡터로 저장합니다. 신규 정책의 효과 추정은 결국
"이 레버 조합이 과거 어느 사례와 유사한가"를 묻는 일이므로, 이 파일이 시스템의
심장입니다.

**현재 모든 항목은 `verified: false`입니다** — 공개자료 기억에 근거한 초안이며
원문 대조를 거치지 않았습니다. 대상 지역 목록이 틀리면 처치군이 오염돼 모든 숫자가
무의미해지므로, 실제 추정 전에 국토교통부 보도자료로 확인하세요.
`run_event_study.py`는 미검증 항목에 대해 기본적으로 실행을 거부합니다.

`announced_date`와 `effective_date`를 분리해 둔 이유는 시장이 발표 시점에 한 번
(예고효과), 시행 시점에 다시 반응하기 때문입니다. 두 기준 모두 돌려서 비교하세요.

식별 자체가 불가능한 설계는 원장에 이유와 함께 표시돼 있습니다. 8·2 대책은 서울
전역이 처치되어 내부 대조군이 없고(→ synthetic control 필요), 12·16 대책은 처치가
지역이 아니라 가격 구간으로 배정됩니다(→ regression discontinuity 필요).

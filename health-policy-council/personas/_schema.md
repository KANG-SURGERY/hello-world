# 페르소나 작성 규격 (persona schema)

각 페르소나는 `personas/<id>.yaml` 한 파일입니다. 하네스와 Claude Code 서브에이전트가
동일한 파일을 읽으므로, 여기 정의된 필드 이름을 바꾸면 양쪽 모두 수정해야 합니다.

## 왜 이렇게 자세한가

페르소나를 "당신은 보건복지부 공무원입니다" 한 줄로 만들면, 모든 에이전트가
비슷한 톤의 중립적 상식을 말하는 데로 수렴합니다. 그러면 회의를 열 이유가 없습니다.
의견이 갈리려면 **이해관계(interests)**, **묶여 있는 제약(constraints)**,
**절대 못 넘는 선(red_lines)**이 서로 충돌하도록 명시돼 있어야 합니다.
`tradeable`(거래 카드)이 있어야 협상 라운드가 성립하고,
`blind_spots`가 있어야 사회자가 각 입장의 구조적 사각지대를 짚을 수 있습니다.

## 필드

| 필드 | 필수 | 설명 |
|---|---|---|
| `id` | O | 파일명과 동일한 ASCII 슬러그. 서브에이전트 이름·인용 키로 쓰임 |
| `name` | O | 한국어 직함 (발언자 표시명) |
| `short` | O | 표·요약에서 쓰는 2~4자 약칭 |
| `bloc` | O | 진영 구분: `정부` / `의료계` / `수요자` / `연구·중립` / `정치` |
| `one_line` | O | 이 사람이 세상을 보는 방식 한 문장 |
| `mandate` | O | 무엇에 대해 책임(또는 대표성)을 지는가 |
| `interests` | O | 이 회의에서 **얻어내려는 것** (3~5개) |
| `constraints` | O | 개인 의견과 무관하게 **묶여 있는 것** (3~5개) |
| `red_lines` | O | 합의문에 들어가면 **서명 거부**하는 항목 (2~4개) |
| `tradeable` | O | 대가를 받으면 **양보 가능한 카드** (2~4개) |
| `evidence_base` | O | 습관적으로 인용하는 데이터·근거의 출처와 종류 |
| `blind_spots` | O | 이 입장이 구조적으로 못 보는 것. **본인은 언급하지 않음**, 사회자·레드팀 전용 |
| `rhetoric` | O | 말투, 논증 습관, 자주 쓰는 표현 |
| `typical_claims` | O | 자주 하는 구체적 주장. 사실검증 대상 후보 |
| `disagrees_with` | O | 구조적으로 충돌하는 다른 페르소나 `id` 목록 |
| `default_seat` | O | `true`면 기본 8인 회의에 포함, `false`면 확대 회의에만 |

## 작성 원칙

1. **캐리커처 금지.** "의협 = 돈만 밝힘", "복지부 = 무능"처럼 쓰면 반박 라운드가
   허수아비 때리기가 됩니다. 각 입장이 **자기 논리 안에서 합리적**이도록 쓰세요.
2. **양보 가능성을 반드시 넣으세요.** 아무도 양보하지 않으면 3라운드(협상)가 빕니다.
3. **red_lines는 진짜 레드라인만.** 5개 넘어가면 그냥 완고한 캐릭터가 되고
   합의문이 영원히 안 나옵니다.
4. **blind_spots는 본인 입으로 말하지 않습니다.** 프롬프트 조립 시 해당 페르소나
   본인에게는 이 필드를 주지 않고, 사회자와 레드팀에게만 전달합니다.
5. 새 페르소나를 추가하면 `disagrees_with`를 **양방향으로** 갱신하세요.

## 검증

```bash
python3 harness/council.py validate
```

필수 필드 누락, `disagrees_with`의 깨진 참조, 기본석 인원수를 점검합니다.
